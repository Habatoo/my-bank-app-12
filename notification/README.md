# Микросервис уведомлений (Notification)

Микросервис **Notification** это асинхронный потребитель событий, отвечающий за сбор, 
регистрацию и хранение истории финансовых транзакций в системе. 
Сервис работает в режиме "только чтение" из очередей сообщений.

### Основные функции:
* **Асинхронный аудит:** Мониторинг топиков Kafka для автоматической регистрации всех финансовых изменений.
* **Формирование истории транзакций:** Консолидация данных о депозитах, снятиях и переводах в едином хранилище.
* **Гарантированная обработка:** Реактивная запись событий в базу данных, исключающая блокировки.

### Взаимодействие через Kafka
Микросервис не предоставляет REST-интерфейсов для записи. Все данные поступают исключительно через брокер сообщений.

**Типы регистрируемых событий:**
1. **CASH_DEPOSIT:** Успешное пополнение баланса.
2. **CASH_WITHDRAW:** Снятие наличных.
3. **TRANSFER_SEND:** Отправка перевода другому клиенту.
4. **TRANSFER_RECEIVE:** Получение перевода от другого клиента.

### Логика взаимодействия
1. **Слушатель (Consumer):** Сервис подписан на системные топики  `Cash` `Account` или `Transfer`.
2. **Обработка:** При поступлении сообщения сервис парсит Payload, определяет тип операции и ID вовлеченных участников.
3. **Персистентность:** Данные сохраняются в PostgreSQL. Используется неблокирующий драйвер R2DBC для обеспечения высокой пропускной способности.

### Разработка и запуск
Сборка только модуля Notification локально:
```bash

./gradlew :notification:bootJar
```

### Запуск тестов
Модуль содержит тесты корректности фильтрации логов и интеграционные тесты сохранения данных:
```bash

./gradlew :notification:test
```
